# Production heartbeat context qualification

The additional Karum single-order check holds one original height request after
a real node-picker recheck. The page must have an accepted market while its
reset heartbeat remains pending. The ordinary picker then refuses an invalid
URL. Its chain, block and exchange fields must clear before that old request is
continued once, with its actual matched Node RPC reply unchanged. The refused
node must stay cleared, including during observed DOM mutations. Retrying the
original node must restore its chain, exchange and exact canonical block.

The independent checker reads the same canonical block hash before and after.
Original account requests, order POSTs, signatures and provider transactions
must keep their counts. No product hooks, state assignments, response bodies or
RPC results are substituted. The controller is exercised in memory separately;
those controls are not actual browser qualification. The hosted execution must
emit ACTUAL-HEARTBEAT-CONTEXT at this exact source before that claim is made.

All original financial profiles, navigation policy, default polling and recheck
intervals, native recovery cases, SQL/root/NoM/client/process oracles and job
deadlines remain unchanged. In particular, the final recovery horizon requires
the actual default 30-second open-order sweep. Existing hosted timing is an
uncontrolled observation; it does not establish CPU attribution or a speedup.

This is a controlled production-page and owned Node RPC test. It does not qualify
physical wallets, public networks, authenticated NoM, release or deployment.
