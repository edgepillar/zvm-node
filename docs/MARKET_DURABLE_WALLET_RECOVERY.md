# Durable wallet publication recovery

This opt-in browser lane keeps every original default-volatile profile and all
nine separately named `durable-ack-*` profiles. The latter use the actual pinned
Relayer CLI from `edgepillar/zvm-relayer` at
`f5d55cce233a90fa962837671b0371004ea56a12`, with Core
`29e6d9b30be94de3772c850c7a1e9811585a8833`. Each process verifies the same
executable identity, size, SHA-256, exact embedded revision and clean-tree flag.

The original queued-ACK milestone is separately qualified at Node
`3949368da5d98753528817ecb5f66e456c4095f2`. Its 79 CLI lifetimes and nine
SIGKILL joins remain historical evidence. New source requires fresh execution;
an unchanged financial oracle does not transfer an old workflow result.

Each of the nine durable two-leg profiles now requires these actual boundaries:

1. The production page receives the original wallet transaction hash from the
   actual CLI. A one-hour posting delay holds one transaction smaller than
   1,024 bytes. Status proves one queued transaction and zero publications.
   Kill and join the owned child; independently inspect its exact queued wire
   record, then reopen the same store and endpoint with the ordinary 10-ms delay.
2. The owned source verifies and retains the actual signed NoM publication, but
   writes no publication RPC response. The original application receipt has not
   executed and source inclusion has not been supplied. Kill and join that CLI,
   join its cancelled HTTP handler, and independently require persisted phase
   `publishing`. Complete actual account history must restore the same bytes as
   posted without another wallet request or publication.
3. Kill the restored posted process, independently require persisted phase
   `posted`, and reopen the same store again. It must still be posted, with one
   original wallet submission and one actual publication. This is a posted
   state written by complete-history recovery.
4. Execute and observe the original first application receipt. The existing
   ordinary reopen must remove its active nonce, retain its audit record and
   original bytes, and precede the second wallet request.
5. After the second normal publication RPC completes, require one posted active
   record and two retained records with the exact total signed bytes. Kill and
   join the CLI, independently require the second record's posted phase, and
   reopen the same store. Require two original wallet requests and two actual
   signed publications, with no duplicate write, before canonical execution.
6. Complete every original receipt, signature, raw-byte, gas, price, partial
   refund, payout, allowance, balance, ownership, replacement/restoration and
   production-browser assertion, and join the final CLI.

The wire oracle opens the actual stopped LevelDB read-only with strict checks.
It independently checks the version-one owner domain, record length, active
state, phase, signed bytes and domain/hash/record checksum. It neither calls the
production admission decoder nor generates a replacement journal.

Each selected store explicitly limits retention to four records and 65,536
logical signed bytes. Default admission remains `volatile`. No operator store
is opened or migrated and no audit bytes are pruned. Logical retention limits
are not physical disk or RSS limits. These are normal-instrumented kernel kills,
not a wallet race-detector or hardware power-loss qualification.

The source retains 52 financial profiles, 1,244 named checks, 70 transactions
and actual test NoM publications, and 63 terminal parent/subtest events. It now
requires 106 joined Relayer CLI lifetimes and 36 actual SIGKILL joins: nine each
at queued, accepted-publishing, restored-posted and normally acknowledged-posted
boundaries. One unchanged Relayer binary and the same built production pages
serve the whole matrix; no extra browser profile or build is introduced.
Fresh complete logs must prove these counts. The original 12-minute main step,
15-minute job and all financial/navigation predicates remain unchanged. The
prior main step took 623 seconds in one workflow; that is not a timing guarantee.

The owned source is a controlled authority, not independent NoM finality.
Unaccepted ambiguous publication remains a fail-closed owner-resolution gate;
this lane does not authorize a guessed retry or implement an operator decision.
Real wallets, independently accepted history/capacity/checkpoint and retention
policies, default-scale workloads, standalone services, vendor compilers,
supported platforms, hardware durability and maintainer/operator acceptance
remain open. All 42 original requirements remain active. Production is `NO_GO`.
